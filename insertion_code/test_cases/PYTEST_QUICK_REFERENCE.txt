COMMAND LINE EXECUTION:

1. Run ALL tests (verbose output):
   pytest insertion_code/test_cases/ -v

2. Run ALL tests (quiet output):
   pytest insertion_code/test_cases/ -q

3. Run specific test file:
   pytest insertion_code/test_cases/test_calendar.py -v

4. Run specific test class:
   pytest insertion_code/test_cases/test_calendar.py::TestCalendarGenerator -v

5. Run specific test method:
   pytest insertion_code/test_cases/test_calendar.py::TestCalendarGenerator::test_calendar_row_count -v

6. Run tests and stop on first failure:
   pytest insertion_code/test_cases/ -x

7. Run tests with short traceback:
   pytest insertion_code/test_cases/ --tb=short

8. Run tests in parallel (requires pytest-xdist):
   pip install pytest-xdist
   pytest insertion_code/test_cases/ -n auto

9. Run with code coverage report:
   pip install pytest-cov
   pytest insertion_code/test_cases/ --cov=insertion_code --cov-report=html
   # Then open htmlcov/index.html in browser

10. Run tests matching pattern:
    pytest insertion_code/test_cases/ -k "calendar" -v  # Only calendar tests
    pytest insertion_code/test_cases/ -k "row_count" -v  # All row count tests

PYTEST FIXTURES (from conftest.py)
================================================================================

SESSION-SCOPED FIXTURES (created once per test session):
  
  spark: SparkSession
    - Provides active SparkSession for all tests
    - Configured with local[2] cluster (2 cores)
    - Automatically stopped after all tests complete
    - Used by: Every test file (dependency injected)

  output_root: str (path)
    - Temporary directory for parquet outputs
    - Created fresh for each test session
    - Automatically cleaned up after tests
    - Used by: All tests reading parquet files

REQUEST-SCOPED FIXTURES:

  temp_dir: str (path)
    - Temporary directory per test
    - Cleaned up after each test
    - Used for test artifacts if needed

HELPER FUNCTIONS (utilities in conftest.py):

  1. assert_dataframe_columns(df, expected_columns)
     - Validates all expected columns present
     - Returns True or raises AssertionError

  2. assert_row_count(df, expected_count, tolerance=0)
     - Validates row count within tolerance
     - Default tolerance=0 (exact match)
     - Supports ±tolerance range

  3. assert_column_values_in_range(df, column, min_val, max_val)
     - Validates all values in [min_val, max_val]
     - Flags out-of-range rows
     - Returns count of violations

  4. assert_no_nulls_in_columns(df, columns)
     - Validates no NULL values in specified columns
     - Accepts list of column names
     - Returns count of NULL values found

  5. assert_unique_values(df, column, expected_count)
     - Validates distinct count equals expected
     - Flags duplicate values
     - Returns actual distinct count

  6. assert_data_type(df, column, expected_type)
     - Validates column data type
     - Supports string type names
     - Handles complex types

  7. assert_value_distribution(df, column, expected_dist)
     - Validates value distribution matches expected
     - expected_dist: dict of {value: count}
     - Returns actual distribution

================================================================================
TROUBLESHOOTING & FAQ
================================================================================

Q: "ModuleNotFoundError: No module named 'pytest'"
A: Run: pip install pytest

Q: "ModuleNotFoundError: No module named 'pyspark'"
A: Run: pip install pyspark==3.3.0

Q: "Parquet file not found at ..."
A: Generators may not have run. Execute all 14 generators before running tests.

Q: "TypeError: _getAttributeNames() takes 2 positional arguments but 3 were given"
A: This is a known Spark 3.3 issue. Upgrade to Spark 3.4+
   Or: pip install pyspark==3.4.0

Q: "Out of memory" when running test_orders.py
A: Increase Spark memory: PYSPARK_PYTHON=python spark-submit --driver-memory 4g ...
   Or: Use .limit() to sample data in assertions

Q: How do I add new test cases?
A: Follow the pattern in existing test files:
   1. Create test method in appropriate test class
   2. Use helper functions from conftest.py
   3. Add docstring with test code (TC-###)
   4. Run: pytest insertion_code/test_cases/test_xxx.py::TestClass::test_method -v

Q: How do I skip a test temporarily?
A: Add @pytest.mark.skip(reason="explanation") decorator
   Or: Use pytest.skip() in test body

Q: How do I mark a test as expected to fail?
A: Add @pytest.mark.xfail decorator

Q: Can I run tests in Docker?
A: Yes, create Dockerfile with:
   FROM python:3.9
   RUN pip install pytest pyspark==3.3.0
   COPY . /app
   WORKDIR /app
   CMD ["pytest", "insertion_code/test_cases/"]
